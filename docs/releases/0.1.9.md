0.1.9 publishes `@open-compute/sdk`, adds the weekly Cloudflare upstream-refresh pipeline, and hardens the self-hosted runtime around deployment admission, Cron recovery, operator proxies, Wrangler uploads, and zero-copy AI Search ingestion. It is for operators who need deterministic single-machine recovery and for developers who manage open-compute from Node.js or Bun.

## What's new

- **`@open-compute/sdk` published.** The new public npm package is released jointly with this `ocd` tag under the same `X.Y.Z`. `createOpenComputeClient({ apiToken, baseURL })` exposes exactly the 140 management operations `ocd` has qualified against the pinned Cloudflare OpenAPI subset, plus 19 open-compute-only vendor operations under `client.openCompute` (capabilities, system status, scheduler, cache, image capacity, upgrade check, Worker endpoints, Durable Object inventory, and KV/D1 backups). Every standard method delegates to the pinned official `cloudflare@7.1.0` implementation, so authentication, retries, pagination, multipart upload, and `APIError` parsing match the official client. Workers resource limits reach users through the official `workers.scripts.settings.get/edit` types.
- **The client cannot fall back to Cloudflare.** `baseURL` is mandatory, absolute, canonical, and must end in `/client/v4`; plain HTTP is accepted only for loopback test addresses; no ambient credential variables are read; and `defaultHeaders` cannot override `Authorization` or platform-internal headers. The Dashboard now consumes the same closed capability surface.
- **The capability inventory is completed.** `GET /open-compute/capabilities` now advertises `GET /open-compute/upgrade/check` and `GET /accounts/{account_id}/queues/{queue_id}/metrics`: routes `ocd` already served but the authority had never registered. Both are also in the SDK surface.
- **Weekly upstream refresh.** A read-only scanner, three-way classification fixtures, and a scheduled workflow compare the pinned OpenAPI, official SDK, and Wrangler identities and classify each candidate as `ready`, `blocked`, or `breaking` against a single tracking issue. Discovery never moves a formal pin, auto-merges, tags, or publishes.
- **Operator-owned outbound honors one frozen proxy policy.** AI providers, target and release checks, and remote S3 use the first configured `HTTPS_PROXY`, `https_proxy`, `ALL_PROXY`, `all_proxy`, `HTTP_PROXY`, or `http_proxy`, with `NO_PROXY` support. Loopback and platform-internal traffic always stays direct; tenant egress is unchanged. Unsupported proxy schemes, credentials, and invalid values fail startup instead of silently bypassing the proxy.
- **Manual AI Search sources.** The namespaced `open-compute:manual` source streams an exact immutable revision from an authenticated loopback provider into the existing parser and indexing pipeline. Source bytes are verified by size and SHA-256 and are never copied into AI Search object storage; official Cloudflare AI Search routes and types are unchanged.

## SDK

- Package: `@open-compute/sdk@0.1.9`, published to the [npm registry](https://www.npmjs.com/package/@open-compute/sdk); install with `npm install @open-compute/sdk`.
- Pins: official `cloudflare@7.1.0` (npm tarball identity recorded in `release.json`), Cloudflare OpenAPI revision `b8687f42e28fbfcb296a350f7dbf16349ea900af`, API surface digest recorded alongside the package identity in `release.json`.

## Fixed

- Wrangler 4.127.1 uploads containing `package_dependencies` now pass the shared strict Script/Versions metadata decoder. The field remains build provenance only and does not change persisted deployment identity or tenant runtime state; malformed entries and unknown fields are still rejected.
- Cron transport-unknown outcomes now consume a durable attempt, keep a fixed 15-minute deadline, and terminalize when retry, deadline, or activation-drain bounds are exhausted. Restarts no longer reset the budget or leave a deployment drain blocked forever.
- A deployment becomes active only after a probe succeeds against one exact workerd startup generation. Unexpected exits uniquely attributable to an active deployment quarantine it and roll back to the newest dispatchable predecessor; ambiguous concurrent incidents recover the runtime without guessing a culprit. Status and support bundles expose bounded, redacted assessment and last-exit evidence.
- The committed OpenAPI authority, capability inventory, and SDK surface now canonicalize through one prettier form across the generator, byte-reproducibility checks, and the pre-commit hook, removing drift between regenerated and committed bytes.

## Before you upgrade

- Stop `ocd` and take a current snapshot before replacing the binary. First startup transactionally applies control V3/V4, scheduler V2, and AI Search V2 migrations. Once opened by 0.1.9, the data directory must not be reopened by 0.1.8.
- Control V3 deliberately quarantines pre-0.1.9 deployments as `DEPLOYMENT_ADMISSION_REQUIRED` and clears their active pointers because they have no generation-bound runtime assessment. Keep Worker sources available and redeploy each Worker after upgrade; no old deployment is silently grandfathered into the new admission model.
- Existing builtin and R2 AI Search locators and derived index state are migrated to the current tagged locator schema. Manual sources are opt-in and require an explicit `[ai.source_providers.<id>]` loopback provider configuration; source bytes are not imported during migration.
- Review the service environment before restart. A non-empty proxy variable is now authoritative and must be a canonical credential-free `http://host:port`; remove unintended inherited proxy values or configure `NO_PROXY` before upgrading.
- Scheduler state is migrated in place with bounded attempts and deadlines. Existing claimed runs retain their durable identity and can become terminal under the new bound rather than retrying indefinitely.

## Install or upgrade

An existing receipt-managed installation can upgrade directly:

```console
ocd upgrade 0.1.9
```

For a new system-wide installation, download and review the installer before elevating it:

```console
curl -fsSL -o install.sh https://raw.githubusercontent.com/elliothux/open-compute/v0.1.9/scripts/install.sh
less install.sh
sudo env OPEN_COMPUTE_RELEASE_TAG=v0.1.9 sh install.sh
sudo /usr/local/bin/ocd setup --yes --system
```

For the default user-owned installation, run the reviewed installer without `sudo`, then run `ocd setup --yes`. Verify with `ocd --version`, `ocd config check`, `ocd doctor`, and `ocd capabilities --json`.

## Security

There are no published security advisories specific to 0.1.9. Management-plane credentials keep their boundaries: deployer and admin tokens never enter tenant isolates, internal listeners stay loopback-only and capability-scoped, and per-generation internal tokens never appear in argv, environment, logs, status, metrics, errors, or tenant-visible responses. The mandatory-`baseURL` design keeps the SDK from defaulting any request to `api.cloudflare.com`. Manual providers are loopback-only and credential references are never persisted with instances; operator proxy credentials are rejected; deployment crash evidence is bounded and redacted before persistence or support-bundle export.

## Known limitations

- Pre-1.0: an official compatibility claim exists only for an `ocd` and `@open-compute/sdk` of the same `X.Y.Z`.
- Selected routes the pinned official SDK does not implement are intentionally absent from the SDK surface even though `ocd` supports them (`PUT …/workers/scripts/{script_name}/usage-model` and `PUT …/r2/buckets/{bucket_name}`); the exclusion is recorded in the selection manifest and the SDK never hand-forges an official method.
- The first npm publish is bootstrapped with an explicitly authorized, short-lived `NPM_ACCESS_TOKEN`; npm provenance via trusted publishing is deferred and tracked as follow-up work.
- Current upstream drift stays `blocked` per the refresh contract and does not move pins: schema HEAD adds optional AI Search `use_ocr`/`custom_metadata` fields and a Queue create `jurisdiction` field that `cloudflare@7.1.0` does not yet express, and Wrangler 4.131.2 awaits its own coordinated evidence review against the pinned 4.127.1.
- The operator proxy supports one credential-free HTTP proxy origin, HTTP absolute-form requests, and HTTPS `CONNECT`; SOCKS, PAC/WPAD, proxy authentication, custom interception CAs, and OS proxy discovery are not supported.
- Manual AI Search providers are loopback HTTP only and do not scan, reconcile, or delete upstream content. The caller must provide the exact revision for each upsert.
- When one unexpected workerd exit has multiple tenant deployments in flight, 0.1.9 records ambiguous attribution and restores service but does not quarantine any tenant automatically.
