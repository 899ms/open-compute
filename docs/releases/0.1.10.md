0.1.10 completes the current Cloudflare API parity batch, gives every local Worker its own `.localhost` origin, and consolidates verified host-child execution behind one bounded runtime owner. It is for single-machine operators who want Wrangler and SDK workflows to stay close to Cloudflare while retaining an explicit, local-only ingress model.

## What's new

- **Local Worker origins.** Each Worker now owns `http://<worker>.<account-id>.localhost:<port>/`. Routing is exact-host and all-path, so Worker code, Static Assets, redirects, SPA fallbacks, and `fetch()` see paths beginning at `/`. The former tenant path ingress is removed rather than retained as an alias.
- **Cloudflare API parity.** The standard surface adds official R2 object listing, Wrangler observability upload fields, atomic observability publication, force-delete recovery, and the current Worker Loader binding contract. D1 migration list/apply remains clearly namespaced under `client.openCompute` because it is an open-compute extension rather than an official Cloudflare endpoint.
- **Artifacts SDK.** `@open-compute/sdk` now includes the 18-operation Artifacts surface through one first-party delegate using the official Cloudflare client transport. Its frozen observed-standard overlay is separate from the pinned official OpenAPI snapshot.
- **Verified host children.** The document parser now uses the shared runtime process owner for verified executable identity, cleared environment, explicit working directory, bounded stdin/stdout/stderr, deadlines, process-group termination, and reaping. Product-specific parser limits and error contracts remain owned by the parser service.

## Workerd

The `third_party/workerd` submodule revision is unchanged from 0.1.9: `d711abf405f2d56b6518a863bb5dbcace14289f1`, with the formal pin `v1.20260905.0-open-compute-p3.d711abf4`. `workerd --version` still prints `workerd 2026-09-05`; the unchanged date string reflects the unchanged runtime pin.

## SDK

- Package: `@open-compute/sdk@0.1.10`, published to the [npm registry](https://www.npmjs.com/package/@open-compute/sdk); install with `npm install @open-compute/sdk@0.1.10`.
- Pins: official `cloudflare@7.1.0`, Cloudflare OpenAPI revision `b8687f42e28fbfcb296a350f7dbf16349ea900af`, and Wrangler `4.127.1`.
- Surface: 141 official operations, 18 observed-standard Artifacts operations, and 21 open-compute extension operations. Standard calls retain official transport, authentication, retry, pagination, multipart, download, and `APIError` behavior.
- Pairing: only an `ocd` and SDK with the same stable `X.Y.Z` are qualified together.

## Fixed

- Worker uploads accept the fixed Wrangler observability bracket fields and commit Deployment, active pointer, and Script observability in one SQLite transaction.
- Worker force deletion persists intent, fences new admission, releases historical Version references, survives restart, and rotates the sole workerd generation when retained runtime references block completion.
- D1 migration application rejects gaps, reordering, changed history, and partial-prefix drift with a stable conflict response.
- R2 listing reuses the authoritative catalog, opaque cursor, metadata reconciliation, and restart-safe storage boundary instead of adding a parallel implementation.
- Host child timeout, cancellation, output overflow, and owner failure all terminate and reap the complete process group without exposing raw child handles or tenant-controlled environment state.

## Before you upgrade

- Stop `ocd` and take a current snapshot before replacing the binary. Startup transactionally applies control migrations V5 and V6; published earlier migrations are unchanged.
- V6 converts each valid legacy Worker route into an authoritative hostname claim and typed all-path route. Inconsistent development data fails closed and must be removed rather than repaired through a compatibility path.
- Update local callers from the removed tenant path to the Worker URL returned by the endpoint API. The response now contains `kind: "local_origin"`, `url`, and `scope: "local_machine"`; the old `path` field is gone.
- `.localhost` origins are local-machine HTTP endpoints. They do not provide public DNS, TLS, remote ingress, or Cloudflare's managed `workers.dev` service.

## Install or upgrade

An existing receipt-managed installation can upgrade directly:

```console
ocd upgrade 0.1.10
```

For a new user-owned installation, download and review the installer, then pin this release:

```console
curl -fsSL -o install.sh https://raw.githubusercontent.com/elliothux/open-compute/v0.1.10/scripts/install.sh
less install.sh
OPEN_COMPUTE_RELEASE_TAG=v0.1.10 sh install.sh
ocd setup --yes
```

Verify with `ocd --version`, `ocd config check`, `ocd doctor`, and `ocd capabilities --json`.

## Security

There are no published security advisories specific to 0.1.10. Worker host authority is canonicalized and resolved before platform paths, unknown or malformed hosts fail closed, internal tokens remain out of argv/environment/logs, and child processes receive only explicitly declared environment values. Force deletion remains restart-safe and does not weaken immutable deployment or external-resource ownership boundaries.

## Known limitations

- `.localhost` endpoints are reachable only through a loopback-bound public listener and are not production HTTPS origins.
- Cloudflare cascades deletion into some associated bindings and Durable Objects; open-compute retains independently owned external resource authority, as recorded by deviation `OC-DEPLOY-001`.
- D1 migration list/apply and local endpoint discovery remain open-compute SDK extensions, not claims of official Cloudflare API routes.
- The macOS document parser still has no enforceable hard memory ceiling; concurrency, input/output, CPU, and timeout bounds remain active.
- Code signing and macOS notarization are not included.
